# Проверка research на одной книге

`dataset-odyssey-agent.json` использует тот же формат, что датасеты в `../dataset`, с полем `"answerMode": "RESEARCH"`. Книга — `../books/Odyssey.txt`. Стартовый набор содержит четыре уже размеченных вопроса: два обычных, один составной и один неответимый. Эталоны и gold chunks для index profile 1 перенесены из существующего датасета «Одиссеи».

Из корня проекта:

```text
/report @data/examples/dataset-agent
```

Одноразовый запуск:

```shell
java -jar build/libs/urag.jar report @data/examples/dataset-agent
```

Последовательность запуска задаётся JSON:

1. Загрузить книгу из `file`, index profiles из `indexProfileIds` и query profiles из `queryProfileIds`.
2. Создать или переиспользовать индекс книги для каждого index profile.
3. Для каждого вопроса запустить `ResearchService` с выбранным query profile. Все поисковые шаги ограничены индексом этой книги и текущего index profile; другие готовые индексы в базе не участвуют.
4. Передать полученный ответ вместе с `expectedAnswer` в `JudgeService`.
5. Записать `report.json` и `compare.json` в `reports/run-<timestamp>/`, а журналы операций — в `.data/logs/`.

В `report.json` сохраняются фактический ответ, вердикт и объяснение судьи, балл, токены, длительность, финальные источники и `research` — поисковые шаги, решения модели и причина остановки. `retrieval.evidenceRecall` показывает покрытие gold chunks финальным контекстом; ранговые MRR/NDCG и Recall@k для research не вычисляются, поскольку его контекст собран из нескольких поисков.

Агент получает только вопрос и найденные фрагменты. Эталонные ответы и gold chunks доступны оценщику, но не передаются агенту. Стартовые поисковые запросы вручную не задаются: первый запрос — вопрос, последующие выбирает модель.

Датасеты без `answerMode` продолжают использовать обычный `AskService`. В одном каталоге запуска нужны одинаковые профили и режим ответа. Для работы требуются доступная Ollama, модели из конфигурации и база с корректными миграциями. Это небольшой пилот; наличие составного вопроса само по себе не гарантирует преимущество агентного поиска.
